## 새로 확인하여 보완한 부분

- **B14:** 옵션 복귀가 스테이지 취소 후 한 프레임만 기다리고, 오류 복구는 별도로 SceneManager를 호출하던 경로가 남아 있었다. 모든 실제 로드를 AsyncSceneLoader로 모으고, 진행 중 전환 종료 후 최신 요청만 실행한다. StageManager는 데이터 준비·씬 준비 콜백을 제공한다. 옵션 복귀는 이전 스테이지의 finally 정리 완료까지 기다린다. 취소·예외 시 활성화 대기 작업을 반드시 마친다.
- **E06:** 실제 HP 감소량 반환은 기존에 구현됐지만 보호막 흡수·처치 정보가 없었다. 기존 float API를 유지하면서 `ApplyDamageDetailed`와 작은 `DamageResult` 값 구조체를 추가했다. 스킬별 추가 클래스는 필요 없다.
- **E10:** 최소 금액만 검사하여 150 Call 같은 비단위 시작값과 50 Call 모델 입력이 허용됐다. `BettingRules`를 기존 모델 파일에 두어 UI·티켓·StageData·빌드 검증이 같은 100 Call 단위를 사용한다. 다음 베팅이 불가능한 잔액도 스테이지 실패로 처리한다. 운영 콘텐츠 수치 자체는 변경하지 않았다.
- **T01/T02:** 완성되지 않은 마지막 로그 줄, HTTP 400/504 상태줄, 예외 메시지 JSON 이스케이프가 남아 있었다. UTF-8 바이트를 줄 끝까지만 소비해 재읽기를 보존하고 실제 HTTP 상태와 JSON 직렬화를 적용했다.
- **T03:** PoolSystemMigration의 미저장 씬 확인과 예외 시 복원, UI 생성기의 다중 씬 복원, 레벨 생성기의 필수 입력 사전 검사를 보완했다. 운영 레벨/프리팹을 재생성하는 메뉴는 이번 검증에서 실행하지 않았다.
- **T05:** GUID 및 소스 참조가 없는 옛 드래그 UI·아이템 상점, 주석뿐인 PropertyDrawer를 제거했다. Unity 내부 툴바 API 호출 실패 시 반복 예외 대신 자동 표시를 중단한다.
- **HUD 추가 결함:** 이전에는 실패 테스트를 과거 계층 기대값으로 분류했으나, 상세 확인 결과 실제 HistoryRoot/Text 참조가 모두 비어 있고 네 번째 행이 중복돼 있었다. 다섯 종류의 내역 행을 연결하고 중복 행을 홀짝 표시로 바꿨다. 기존 디자인과 레이아웃 그룹을 재사용했다. 테스트는 특정 이름의 부모 노드 대신 실제 참조와 확정 티켓 표시를 확인한다.

## 테스트 정리 기준과 결과

- 저장 실패·원자적 파일 교체·아이템 롤백·풀 소유권/중복 반환 검사는 유지한다.
- ExtensibilityRegressionTests에 ReviewRegressionTests를 합쳐 생성 객체 정리, 전투 초기화, 직렬화 필드 접근을 공유한다. 두 파일의 회귀 시나리오는 유지한다.
- Prist/Wizard의 개별 에셋 검사와 StageLevelDesignTests의 과거 튜닝값 검사를 UnitBasicAttackTests의 운영 콘텐츠/참조 검사로 통합한다. 회복 수치는 테스트용 설정으로 SkillSystemTests에서 검증하고, 실제 Skill 애니메이션 연결 검사는 유지한다.
- NUnit과 중복된 StageBettingVerification 수동 메뉴를 제거한다. 빌드에서 비활성이고 임시 Phase 0-B에 종속된 1,100줄 이상의 시각 검증 하네스도 제거한다. 현재 UI의 실제 MCP 캡처 검증은 계속 수행한다.
- 실패를 숨기기 위한 Ignore 추가나 운영 밸런스 수정은 하지 않는다. 배팅 내역의 연결 누락은 제품 코드를 고쳤다.

- NUnit 테스트 파일 **18→14개**, 소스 **6,055→5,751줄**. 별도로 중복 수동 검사 127줄과 Phase0BVisualVerifier 1,270줄을 제거했다. 금액 경계처럼 다른 입력 조합은 TestCase로 유지하므로 테스트 케이스 수 자체를 줄이는 것을 목표로 삼지 않았다.
- 전체 실행: **230개 중 229개 통과, 실패 0개, 기존 Ignore 1개**. 건너뛴 항목은 현재 사용하지 않는 PerspectiveLegacy 세로 화면 제약이다. 이번에 Ignore를 추가한 것은 아니다.
- 첫 MCP 테스트 요청은 Test Runner 초기화 시간 초과로 실행되지 않았고, 재요청에서 위 결과를 얻었다.

## 실제 전환·화면 검증

- 씬 활성화 전 로비에서 즉시 취소, Loading 진행도 100%에서 취소·복귀 연속 입력, 이후 재진입을 Unity MCP Play Mode에서 실행했다. 로비 복구 후 `IsStageRunning=False`, `IsLoading=False`를 확인했다. 즉시 취소 시 로비 씬 이름만 보고 요청을 무시하던 조건도 수정했고, 남은 페이드 오버레이를 해제했다.
- 재진입 후 인트로 입력 허용 시점에 탭하고 배팅을 확정하여 실제 전투 HUD까지 진행했다. 검증용 특수 배팅 조합은 메모리에서 준비했으며 운영 스테이지/저장 파일을 변경하지 않았다.
- 휴대폰 360×800과 태블릿 768×1024을 캡처하고 이미지를 직접 열어 확인했다. 첫 캡처에서 일부 항목 제목이 검정 배경 위 검정 글씨로 보이지 않는 문제를 발견해 기존 첫 행과 같은 흰색으로 통일했다. 재캡처에서 항목 제목·표시값과 겹침/잘림을 확인했다.
- 휴대폰은 실제 확정한 티켓의 네 항목을 표시한다. 태블릿은 동일한 실제 HUD에 별도 메모리 컨텍스트를 주입하여 남은 ‘생존 행’ 종류를 포함한 네 항목을 표시한 검증 화면이다. 실기기 화면 캡처는 아니다.
- Android 기기 페이싱·GPU/발열·첫 소환 비용은 미측정으로 남는다.
- 실제 로컬 TCP로 인증 헤더를 분할 전송해 200 응답, 인증 누락 시 401, 16KB 헤더 한도에서 400 상태줄을 확인했다. 실제 15초 게이트웨이 타임아웃 유도는 하지 않았으며 504 상태 매핑은 회귀 검사로 확인했다.
- 전체 테스트 이후의 즉시 취소 조건·페이드 복구 수정은 위 Play Mode 경로로 검증했다. 최종 프리팹 제목 색상은 재캡처로 검증했다. 마지막 Unity 컴파일 완료 및 빌드 콘텐츠 검사 오류 0건, `git diff --check` 통과.
