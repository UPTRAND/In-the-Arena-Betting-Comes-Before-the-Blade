# 구조 점검과 구현 결과

> 2026-09-21 정리: 사용자 요청에 따라 임시 검증 스크립트·캡처·결과 원본을 삭제했다. 아래 내용은 당시 실행 및 직접 이미지 확인 결과의 기록이다.

확인일: 2026-09-19. 작업 도구: Unity MCP(연결 중단 후 로컬 HTTP MCP 클라이언트로 재연결), 소스 검색, Unity EditMode 테스트, 실제 Game View/Device Simulator 캡처.

## 설계 판단

기존 `StageManager → RoundManager → Phase` 진행 경계와 저장 후보의 검증·저장·반영 경계는 유지한다. 큰 클래스를 일괄 분할하면 기능 수정 시 찾아야 하는 파일만 증가한다. 이번에는 스킬 작성자에게 요구되던 정의/런타임 이중 구현을 없애고, 기존 파일 안에서 실행·수명·실패 처리를 보강했다. 새 런타임 컴포넌트는 공통 반응형 Canvas 하나다. 스킬 Inspector 선택 도구와 회귀 테스트는 에디터 전용이다.

## 구현한 보완

| 영역 | 문제 | 구현 |
| --- | --- | --- |
| 스킬 작성 | 행동마다 정의와 Runtime 클래스를 작성 | 공용 실행 어댑터와 유닛별 설정 복제. 기존 네 행동을 단일 클래스로 전환 |
| 스킬 편집 | 관리 참조를 편리하게 선택할 UI 부재 | Behavior/Targeting/Effect 타입 검색 메뉴, 설정 펼침, Undo 지원 |
| 타기팅 | 기본 공격 사거리 안에서만 액티브 판단 | 스킬 자체의 대상/사거리/조건을 먼저 검사. 적 탐색 대기 중 자기 대상 스킬도 판단 |
| 타기팅 | Any가 아군만 검사, 범위 대상이 시전 중 이동해도 유지 | 양 팀 수집, 시전 완료 시 범위 대상 재구성 |
| 스킬 실행 | 부분 효과 성공 후 후속 실패가 재실행으로 이어질 수 있음 | 성공 보존 및 쿨다운 확정. 회복량 0은 성공에서 제외 |
| 수명 | 쿨다운이 종료 이벤트를 막음, 해제 후 참조 잔류 | 전투 생명주기 이벤트 전달, 멱등 해제, 외부 유닛의 런타임 시전 거절 |
| 상태 효과 | 주기 피해로 사망 시 효과 목록이 비워져 순회 실패 | 콜백 후 목록과 해당 효과의 동일성을 다시 검사 |
| 이벤트 | 큐 포화 시 즉시 재귀 dispatch | 틱 처리 상한과 포화 계수. 초과 시 재귀 실행하지 않음 |

| 공간 검색 | 최대 검색 거리와 정확히 일치할 때 null 비교 | 동일 거리 tie-break 전에 기존 후보 null 검사 |
| 풀 | 동명 프리팹 세 번째 등록 시 문자열 별칭 부활 | 등록된 풀 전체에서 유일한 이름만 별칭으로 제공 |
| 진행 | 중복 스테이지/라운드 시작, 활성화 대기 중 씬 취소 | 중복 실행 방지, 진행 중 씬 로드 완료 후 복구, 복구 페이드 해제 |
| 저장 진단 | 오류 메시지 자체가 깨져 로그 기대 검증 실패 | 손상/IO 실패 두 메시지 복구. 저장 규칙은 유지 |
| UI | 픽셀 고정 배율, 폭만 따라가 화면 밖으로 밀림 | 디자인 기준 크기를 안전 영역 안에 균일하게 맞추고 여유 공간은 앵커로 확장 |
| UI 배경 | 태블릿 로비 배경 양옆 검은 여백 | 원본 비율 유지 + EnvelopeParent. 배경 교체 시 비율도 갱신 |
| 전투 UI | 긴 화면에서 아이템 행이 큰 빈 공간으로 늘어남 | 하단 콘텐츠 높이 유지, 전투 뷰포트가 남는 높이/폭 사용. 씬과 HUD 프리팹 반영 |

## 시스템별 검토 범위와 남은 판단

자체 스크립트의 매니저, 전투/배팅/정산, 저장, UI, 카메라, 유닛, 입력/오디오, 유틸리티/풀 경계를 검토했다. 소스 정적 검토와 자동 테스트, 화면 실행 검증을 구분한다. 모든 조합과 모든 실행 경로가 검증됐다는 의미는 아니다.

| 범위 | 검토 사항 | 유지/후속 판단 |
| --- | --- | --- |
| Managers 및 Input/Sound/Catalog | 싱글턴 수명, 씬 재바인딩, 비동기 취소, 이벤트 구독 | 진행 취소 경계 보완. UIManager의 이름 기반 등록은 동명 UI를 쓰는 확장 시 Type/등록 소유권 방식 개선 대상 |
| Stage/Round/Betting/Combat/Result | 흐름, 중복 시작, 스폰/회수, 전투 종료, 배팅 검증, 정산 | 밸런스와 라운드 콘텐츠는 수정하지 않음. RoundRule의 미구현 옵션은 게임 규칙 확정 후 구현 필요 |
| ItemData/Service/Executors/Coordinator/Usage/Chest | 구매·사용 경계, 재고, 적용/실패, 취소, 프리뷰 | 기존 트랜잭션 경계를 유지. 상자 연출 프리팹 누락 시 차감 후 표시 실패 가능성은 자산 검증 개선 대상 |
| Save 11개 파일 및 SaveManager | 후보 복제, 검증, 버전 이동, 백업/원자적 저장, 재시도 | 실패 시 원본 상태를 유지하는 구조 보존. 기존 깨진 주석/문자열 전체를 추측하여 재인코딩하지 않음 |
| Unit/AI/Action/Stat/Registry/Spatial/Engagement | 실행 상태, 탐색, 이동, 피해/회복, 풀 재사용, 사망 콜백 | 주요 경계 수정. 108 유닛 제한은 풀·공간 버퍼·타깃 버퍼의 공동 제약으로 유지 |
| Skill/Status/Projectile/VFX/HP/Animation | 공유 설정과 실행 상태, 이벤트 순환, 시전 후 대상 검증, 풀 준비/해제 | 단일 클래스 확장 제공. 상태 효과는 기존 별도 데이터 모델 유지. 특수 애니메이션 상태의 일부 구체 타입 의존은 후속 데이터화 대상 |
| UI 전체 화면·팝업·아이템 조작·보상·페이드 | Canvas, 안전 영역, 앵커, 동적 생성, 화면 전환, 이벤트 해제 | 반응형 공통 처리 및 실영상 확인. 비활성 구형 UI/`#if false` 코드 정리는 참조 이관을 별도로 확인한 뒤 수행할 항목 |
| Camera 5개 파일 | 실제 UI viewport, 배경 안전 평면, 프레이밍, 줌 제약 | 변경한 뷰포트를 기존 계산기가 사용하도록 연결. 비사용 Perspective 프레이밍의 고정 aspect는 해당 모드 활성화 시 재설계 대상 |
| AsyncSceneLoader/LoadingProgress/Timer/Controls/FrameRate | 취소, 진행 표시, 시간 기준, 입력 표시 | 구조 유지 |
| Pool 7개 파일 | 키 충돌, 반환 중 콜백, 파괴된 인스턴스, scope 해제 | 동명 별칭 수정. 기존 프리팹 참조 기반 키를 확장 시 우선 사용 |
| 에디터/진단 | 마이그레이션, 에셋 테스트, 시각 검증 하네스 | 전체 EditMode 실행. `PHASE0B_VISUAL_VERIFIER` 전용 진단은 일반 빌드 코드와 분리된 조건부 도구로 유지 |

검토에서 드러난 미구현 규칙·콘텐츠 기대값 차이를 임의의 새 게임 사양으로 확정하지 않았다. 위 표의 후속 항목은 이번 변경에서 구현한 항목과 구분한다.

## UI 검증 증거

검증 당시 캡처한 이미지 파일을 실제로 열어 확인했다. 비율 수식만으로 통과 판정하지 않았다.

| 화면 | 확인한 조건 |
| --- | --- |
| 타이틀 | 수정 전후, 360×640 |
| 로비 | 360×640, 768×1024 배경 수정 전후 |
| 유닛 목록 | 768×1024 |
| 스테이지 소개/배팅 | 태블릿 |
| 전투 일반 휴대폰 | 360×640 |
| 전투 긴 휴대폰 | 360×800 |
| 전투 태블릿 | 768×1024 |
| 노치/하단 안전 영역 | Device Simulator 1170×2532, safe area (0,102,1170,2289) |
| 노치 타이틀/로딩/로비/동적 팝업 | Device Simulator 1170×2532 |

1080×1920과 HUD 콘텐츠 높이는 기존 디자인 좌표이며 기기별 분기가 아니다. 화면 배율은 실제 가용 영역에서 계산하고, 전투 화면은 앵커로 남은 공간을 채운다. 노치/홈 표시 영역은 조작 대상에서 제외한다. 현재 모바일 세로 UI를 기준으로 검증했으며 가로 전용 레이아웃과 실제 Android 기기의 성능·터치/IL2CPP 빌드는 별도 검증 범위다.

## 테스트

기준선은 195개 중 10개 실패였다. 새 회귀 테스트 16개를 추가했다. 최종 전체 실행은 **211개 중 205개 통과, 기존 실패 6개**다. 신규 테스트는 모두 통과했고 회복량 0 성공 처리 및 저장 오류 로그 검증 실패 3개를 해소했다. 콘텐츠 기대값 차이 5개와 과거 Battle HUD 계층 기대 차이 1개는 남아 있다. MCP 실행 결과를 확인했다. 재시작 직후 MCP 테스트 초기화가 지연된 실행은 결과에 포함하지 않고, 실제 211개 완료된 실행만 기준으로 삼았다.

사용자가 `D:\WIKI\TKB` 경로를 무시하도록 명시했으므로 외부 위키는 수정하지 않았다. 계획·작성 가이드·점검 결과를 이 저장소 DevLog에 남겼다. 기존 Packages/Resources/Settings 변경은 보존하고 자동 커밋/푸시는 수행하지 않았다.
