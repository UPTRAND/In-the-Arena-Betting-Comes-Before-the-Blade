# 개발 편의성·반응형 UI 개선

> 2026-09-21 정리: 사용자 요청에 따라 임시 검증 스크립트·캡처·결과 원본을 삭제했다. 아래 내용은 당시 실행 및 직접 이미지 확인 결과의 기록이다.

## 목표와 원칙

- 스킬 하나는 `SkillBehaviorDefinition` 상속 클래스 하나에서 설정, 대상 선택, 실행, 주기 처리, 이벤트 반응, 해제를 작성한다.
- 기존 SkillData 에셋과 SerializeReference 타입/필드 이름을 유지한다. 기본 제공 Targeting/Effect는 선택적으로 재사용한다.
- 구조를 더 작게 나누는 것 자체를 목표로 삼지 않는다. 저장 트랜잭션, 풀, 전투 스케줄러처럼 이미 책임이 명확한 경계는 유지한다.
- 변경 함수에는 기능 주석, 명시적 중괄호와 섹션 간 빈 줄을 사용한다. 새 코드에서는 삼항식과 익명 콜백을 피한다.
- UI는 기기별 숫자 분기 없이 디자인 기준 크기, 안전 영역, 앵커와 가용 영역으로 배치한다. 실제 Unity Game View 이미지를 확인한다.

## 확인한 구조

`Managers → StageManager → RoundManager → Betting / Combat / Result`가 진행을 소유한다. `Unit`은 공개 API와 상태를 소유하고 `BattleSimulation`이 AI/스킬/상태효과/이동을 갱신한다. `SkillData`는 타기팅/효과/행동을 조합하지만 행동마다 별도 Runtime 클래스를 요구한다. 아이템은 UI→Coordinator→Service→Executor 순서이며 저장은 복제 후보→검증→파일 저장 성공 후 반영한다. 풀은 범용 Factory와 유닛/투사체/UI 어댑터를 사용한다.

## 구현 순서

1. 자체 스크립트 전체의 구조·호출·수명·하드코딩·직렬화 경계를 점검하고 기존 EditMode 테스트 결과를 기록한다.
2. 공통 행동 런타임이 스킬별 설정을 복제하고 생명주기를 전달하도록 개선한다. 기존 네 행동을 단일 클래스 방식으로 바꾸고 커스텀 대상 선택/투사체 준비 확장점을 연결한다.
3. 스킬 실행의 실패/부분 성공/재사용/해제와 타기팅 경계를 검증한다. 새 확장 코드로 인해 프레임이 무한히 잠기지 않게 이벤트 처리량을 제한한다.
4. 공통 반응형 Canvas와 안전 영역 처리를 씬에 연결한다. 전투 HUD의 화면 높이에 종속된 앵커/오프셋을 실제 가용 영역에 맞춘다. 런타임 생성 UI도 확인한다.
5. Unity MCP 컴파일·회귀 테스트, 일반 휴대폰/긴 휴대폰/태블릿 Game View 스크린샷으로 검증한다.
6. 최종 diff, 파일별 점검 범위, 구현한 보완점과 별도 설계가 필요한 항목을 기록한다.

## 변경 전 상태

- 자체 스크립트 124개(에디터 테스트/시각 검증 스크립트 포함), 실제 게임 씬 Title/Loading/Lobby/MainGame, 보조 Debug 씬.
- Title/Lobby/Debug Canvas는 ConstantPixelSize, MainGame/Loading은 1080×1920 기준 ScaleWithScreenSize와 폭 우선 배율이다.
- MainGame HUD에는 고정 높이 카메라 영역과 전체 stretch에 큰 음수 sizeDelta를 더하는 아이템 영역이 함께 존재한다.
- 변경 전 EditMode: 195개 실행, 실패 10개. 사제/마법사·스테이지 데이터 기대값 차이 5개, 회복 0일 때 성공 처리 1개, 저장 오류 문자열과 테스트 기대값 차이 3개, HUD 프리팹 경로 기대값 1개.
- 기존 미커밋 Resources/Settings/Packages/ProjectSettings 변경은 이 작업 시작 전부터 존재했다.
- 사용자가 외부 위키 경로 지침을 무시하도록 명시했다. 외부 위키는 갱신하지 않는다.

## 최종 구현 및 검증

- 단일 클래스 스킬, Inspector 타입 선택, 타기팅/실행/해제 경계, 이벤트 큐, AI 사거리 판단, 풀 이름 충돌, 진행 취소 복구를 구현했다.
- Title/Loading/Lobby/MainGame에 공통 반응형 Canvas를 연결했다. 로비 배경과 전투 HUD 씬/프리팹의 배치를 보완했다.
- 일반 휴대폰(360×640), 긴 휴대폰(360×800), 태블릿(768×1024), 노치 기기(1170×2532)의 실제 렌더 이미지를 열어 확인했다. 전투 화면 수정 전후 비교 자료를 보존했다.
- 최종 EditMode: **211개 실행, 205개 통과, 기존 실패 6개**. 신규 회귀 16개 모두 통과. 기준선 실패 10개 중 4개 해소. MCP 실행 결과를 확인했다.
- 남은 실패: 사제 회복 기대값 82.5/실제82, 사제 HP100/실제70, 마법사 HP85/실제50, 스테이지 라운드 수6/실제7, 도입 유닛 Wizard/Knight 차이, Battle HUD의 과거 BettingGroup 계층 기대 차이. 밸런스 및 UI 콘텐츠 사양 확인이 필요한 기존 항목이다.
- 구조 검토와 후속 판단: `2026-09-19-structure-audit.md`. 새 스킬 작성법: `2026-09-19-skill-authoring.md`.
- 실제 Android 기기/IL2CPP 빌드와 가로 전용 UI는 검증하지 않았다. 전체 실행 경로의 무결함을 보장하는 결과가 아니다.
