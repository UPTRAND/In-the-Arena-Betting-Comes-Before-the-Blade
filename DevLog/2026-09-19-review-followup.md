# 첨부 검토 제안 후속 구현

> 2026-09-21 정리: 사용자 요청에 따라 임시 검증 스크립트·캡처·결과 원본을 삭제했다. 아래 내용은 당시 실행 및 직접 이미지 확인 결과의 기록이다.

이 단계의 범위는 사용자가 첨부한 대화 본문의 제안이었다. 당시에는 링크만 표시된 별도 42항목 보고서가 제공되지 않아 본문의 재현 경로와 제안을 소스에 대조했다. 이후 상세 보고서가 제공되어 [42항목 대조 및 테스트 정리](2026-09-19-review-reconciliation.md)를 추가로 수행했다. 최신 검증 결과와 기존 테스트의 통합·제거 근거는 해당 문서를 기준으로 한다.

## 실행 순서

1. 결과 조기 입력, 상태 효과 콜백·풀 재사용, 유닛 갱신/범위 피해 중 목록 변경, 저장 실패 화면을 먼저 보완한다.
2. 무기 기본값/버프 합성, 피해·보호막, 강제 이동, 실제 AI 선택, 전투 시간/종료 경계를 정리한다.
3. 공격 메타데이터·HUD·풀 대여·VFX의 반복 비용과 빌드 HP바 참조를 보완한다.
4. 데이터·도감·확정 스냅샷·에디터 도구·보상 취소 등 나머지 항목을 대조하고 필요한 변경을 반영한다.
5. Unity MCP 컴파일/회귀 테스트, 실제 결과·저장 실패 UI 캡처, 가능한 로컬 성능 비교를 수행한다. Android 실기기 결과는 연결된 기기가 없으면 측정했다고 주장하지 않는다.

위키 경로는 이전 사용자 지시에 따라 사용하지 않는다. 코드 작성 시 명시적 중괄호, 함수 설명, 역할별 빈 줄을 유지하고 익명 콜백/복잡한 삼항식을 피한다.

## 반영 내역

| 첨부 제안 | 구현·검토 결과 |
|---|---|
| Result 조기 클릭 | `ResultPhase` 완료 객체를 Prepare에서 생성. Enter는 같은 객체를 대기하고 완료 후 연출을 재개하지 않음. |
| 상태 효과 콜백 중 반환 | 실행 깊이·논리 제거·지연 해제/풀 반환, 대여 세대 스냅샷 도입. 제거 중 신규 적용 방지. |
| 유닛 목록 변경 | 중앙 틱과 프레임 순회 시작 시 `UnitHandle` 목록 확정. |
| 폭발·모루 대상 누락 | 범위 내 대상 핸들을 먼저 모은 뒤 피해 적용. 재사용 목록 풀 사용. |
| 저장 실패 화면 | 최초 저장 전에 패널 준비, 실패/저장 중 모드 표시, 실패 후에도 재시도/포기 접근. 복구 버튼 실제 프리팹 연결. |
| 공간 인덱스 반경 경계 | 이전 변경의 동일 반경 null 검사 유지. |
| 무기와 버프 합성 | 무기 능력치를 기본값에 적용한 뒤 버프/디버프 합산. |
| 피해 의미 | `DamageContext.IgnoreDefense` 추가. 일반 피해는 방어→치명타→보호막→체력 순서. 고정 피해는 방어만 생략. 반환/이벤트 값은 실제 감소 HP로 제한하므로 과잉 피해는 흡혈량에 포함하지 않음. |
| 강제 이동 | Unit 내부 강제 이동 상태가 공격/시전/AI 목적지보다 우선. 시전 및 발사 대기 취소, 전장 경계 적용. |
| AI 스킬 선택 | 이전 독립 사거리 검사 유지. 실제 `UnitDecisionAgent.UpdateAI`의 적 없는 회복 경로 회귀 테스트 추가. |
| 실행 모드/부분 성공 | 이전 수정 유지. 패시브에는 Behavior 필수 검증 추가. 실제 Hunter 에셋이 EffectsOnly인 오류를 BehaviorOnly로 수정. |
| 빌드 HP바 | 동일 GUID의 프리팹을 Resources/UI/World로 이동. 에디터 전용 로드 분기 제거, 빌드 검증 추가. |
| 전투 시계 | 고정 틱에서 유닛·투사체·모루 처리. 제한 시간은 누적 처리 시간으로 감소. 투사체·모루 표시 보간 분리. 준비 중 시간 정지. |
| 결과 확정 | FreezeBattle로 큐/투사체/모루 중단 후 스냅샷 생성. 종료 알림 즉시 전달, 시전/이동 취소. 이후 피해·회복·효과 적용 차단. |
| 공격 클립/로그 | 컨트롤러 변경 시 공격 클립 캐시 갱신. 전투 로그는 Conditional로 비개발 빌드 인수 평가까지 제거. |
| HUD 반복 작업 | 전체 갱신은 바인딩/이벤트, 시간은 표시 초 변화, 입력 상태는 상태 변화 때 갱신. BettingPhase 참조 캐시. |
| 풀 대여 | 정상 경로는 stack pop. 가용 객체가 없고 용량 경계에 도달했을 때 파괴 객체 정리. |
| VFX/모루 생성 비용 | 기존 ObjectPoolingFactory 재사용. 프리팹당 최대 108, 라운드 종료 회수. VFX 컴포넌트 배열 캐시·재생 초기화. |
| 예약 검색 구조 | EngagementSlotSystem의 선형 예약 목록 유지. 별도 자료구조가 필요하다는 측정 근거가 없어 복잡성을 늘리지 않음. |
| HP바 갱신 | 위치 추적은 매 프레임 유지, HP/최대 HP가 같으면 fill 변경 생략. |
| 탐색 비교 | 20/54/108 유닛에서 그리드 재구축을 포함한 최근접 탐색과 선형 탐색 비교. 동일 배치에서 대상 불일치 0건. 아래 측정 참조. |
| Android/프레임 정책 | FrameRateManager로 정책 단일화. adb 장치 목록 비어 있음. 실기기 프레임 페이싱은 미측정. |
| 효과 지속 시간 | 최종 durationOverride로 영구 여부 결정. 0은 영구, 음수는 원본 사용. 보호막 소진은 명시 Expire. |
| 대상 정책 | SingleUnit 기본 고정, 선택적으로 대상 상실 시 재탐색. GroundAtTarget은 선택한 지점 고정, Area는 완료 시 범위 재수집. Any는 양 팀. |
| 생존/대여 한도 | 살아 있는 유닛 108과 사망 연출 포함 대여 216을 분리. 무제한 생성하지 않음. |
| 확정 데이터 | 배팅 확정 후 선택 변경 금지. 결과 행/실패 항목은 입력 목록 복사와 읽기 전용 래핑. |
| 콘텐츠 검증 | 실제 빌드 의존성과 Resources가 참조하는 스테이지 검사. 최소 베팅액, 미지원 특별 규칙, 편성 상한, 유닛·공격·스킬 참조 및 HP바 검사. 미사용 과거 스테이지 에셋은 현재 빌드 오류로 취급하지 않음. |
| 도감 여러 스킬 | 기존 설명 영역에서 아이콘 클릭으로 순환, 현재 번호/전체 개수 안내. 별도 스킬별 화면 클래스 추가 없음. |
| VFX 위치/수명 | SkillVfxRequest에 FollowTarget과 StopOnTargetDeath 분리. 지점 VFX 기본은 고정·대상 사망과 독립. 코드로 각 정책 별도 지정 가능. |
| Hermes 로그/TCP | StreamReader leaveOpen + 읽은 Position 저장. HTTP 헤더 종료까지 누적 읽기, 16KB/2초 제한 유지. |
| 생성기 안전성 | 예제용 UnitData 복제, 실제 Knight 덮어쓰기/레거시 Heal 삭제 제거. 레벨 폴더 자동 삭제 제거. 덮어쓰기 범위 안내, 씬 UI 생성 전 미저장 씬 처리. |
| 보상/비활성 코드 | 보상 Sequence를 실제 핸들로 저장·중단. HUD의 #if false 블록 제거. |
| 리플렉션/문서 도구 | ScreenFader.ConfigureOverlay로 비공개 필드 리플렉션 제거. PDF 생성기의 한글 폰트 경로를 환경 변수로 지정 가능. PDF 자체는 이번 작업 대상이 아니므로 재생성하지 않음. |

## 측정과 검증

- 최종 전체 실행: **227개 중 221개 통과**, 추가한 `ReviewRegressionTests` **16개 전부 통과**. 기존 실패 6개 유지.
- Unity Editor CPU 탐색 마이크로벤치마크(200배치 평균, 배치마다 모든 유닛 조회, 그리드는 재구축 포함): 20유닛 0.0073ms/선형 0.0141ms, 54유닛 0.0263ms/선형 0.0968ms, 108유닛 0.0600ms/선형 0.3869ms. 에디터의 특정 배치 결과이며 Android 성능이나 전체 프레임 향상 수치가 아니다.
- 실제 빌드 의존 콘텐츠 검사: 오류 0건. Hunter 실행 모드 수정 전에는 검증에 실패했고 수정 후 통과했다.
- 최종 소스/프리팹 반영 뒤 Unity 재컴파일 완료, 콘솔 오류 0건, 콘텐츠 검사 오류 0건. `git diff --check` 통과. 최종 테스트 이후에는 제목판 배치·표시 설정과 주석·중괄호·미사용 필드 정리를 반영했으며, 화면 확인 및 컴파일 검사로 검증했다.
- Android SDK의 adb 실행 결과 연결 장치 0대. 프레임 페이싱 비교는 연결된 실기기에서 추가로 수행해야 한다.
- 첫 저장 실패 태블릿 캡처에서 배경 투과/작은 버튼 글자/목표 금액 초기값을 직접 발견하고 수정했다. 360×800, 768×1024, 1170×2532 화면을 실제 캡처하고 이미지를 열어 확인했다. 마지막 크기는 노치 안전 영역도 적용했다. 저장 실패 안내와 재시도·포기 버튼의 겹침/잘림이 없는 것을 확인했다.
- 도감 스킬 이름의 긴 순환 안내가 설명과 겹치는 것을 캡처에서 발견했다. 안내를 번호 중심으로 줄이고 제목판 폭을 설명 영역에 맞췄다. 실제 버튼 입력으로 1/2→2/2→1/2 순환을 확인했으며, 360×800에서도 최종 이미지를 확인했다.
- 실제 플레이에서 배팅 확정→전투→타임아웃 결과→계속 입력→2라운드 배팅을 확인했다. 결과 확정 뒤 논리 전투 시간이 10.75002초에서 유지됐고, 다음 라운드의 확정 배팅은 초기화됐다. 저장 실패는 후보 데이터가 없는 경로로 재현했으며, 실제 디스크 장애/Android 저장 장애를 재현한 것은 아니다.
- 에디터에서 수명 함수를 명시 호출하는 별도 풀 검사로 VFX/모루의 동일 객체 재대여와 VFX 크기 초기화를 확인했다. 실제 기기 부하 시험과는 구분한다.
- 두 PDF 생성기 Python 구문 검사 통과. PDF는 재생성하지 않았다.

### 직접 확인한 최종 화면

| 확인 대상 | 캡처 |
|---|---|
| 저장 실패 / 휴대폰 | 360×800 |
| 저장 실패 / 태블릿 | 768×1024 |
| 저장 실패 / 노치 안전 영역 | 1170×2532 |
| 실제 전투 / 결과 | 전투, 결과 |
| 복수 스킬 순환 / 제목판 | 두 번째 스킬, 휴대폰 |

기존 실패 6개는 Prist 회복량/HP, Wizard HP, 스테이지 라운드 수/초기 편성, HUD의 과거 BettingGroup 구조 기대값이다. 근거 없이 게임 밸런스를 테스트의 과거 값으로 되돌리지 않았다.
